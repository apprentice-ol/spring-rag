# requirements/ — 接口与交互预期规格（测试的权威载体）

<!-- 脚手架: 按域一文件；条目随深测逐步长全；改预期须用户确认 -->

本目录是**执行结果的预期标准**：深测（pipeline-api-test skill 深测循环）逐单元测试前先读这里；
**编译通过不算数，执行结果符合预期才算数**；实测与条目不符即异常，进修复循环。
`grep -c '✅ 已验证' **/*.md` 即接口覆盖率——本目录同时是**活覆盖清单**。

## 文件组织（按域）

- `api-<域名>.md` — 后端接口预期（如 api-ingestion.md / api-storage.md）
- `web-<页面名>.md` — 页面交互预期

## 条目格式

```markdown
### <METHOD> <path> — <一句话语义>
- 状态: ⏳ 未验证 / ✅ 已验证@<runId> / ❌ 偏差处理中
- 抽检: Y/N   ← Y = 回归抽检集（每域 ≥1 成功路径 + 全部已知异常路径代表；默认收尾回归只跑抽检集，全量仅发版前）
- 前置: <依赖的数据/状态，如"已存在名为 X 的记录"；无则写"无"
- 成功：2xx + 响应含 <关键字段/结构>
- 异常：<错误输入> → 4xx，message 含 <友好提示>
- 兜底：未知错误 → 统一错误体（不裸堆栈）
- 来源/变更：<日期 或 引用的计划/需求文档>；改预期须用户确认
```

## 纪律

- **无条目的接口**：深测时先补写条目（作为 run 产出物入库）再测——条目随测试逐步长全，是活文档
- **预期变更 = 需求变更**：必须用户确认后落条目，不静默改
- 与台账异常登记表分工：登记表记处置过程，条目沉淀最终口径
- **seed 前置**：条目"前置"字段声明的数据，深测时先备（IDEA MCP `execute_sql_query` 或 Apifox 测试场景链）

## 全局异常契约（所有接口适用，GlobalExceptionHandler 统一实施）

| 场景 | HTTP | message 特征 |
|---|---|---|
| 缺必填 query 参数 | 400 | `缺少必填参数: <name>` |
| multipart 缺文件部件 | 400 | `缺少上传文件部件: <part>` |
| 请求体 JSON 非法 | 400 | `请求体格式错误（JSON 解析失败）` |
| 路径/参数类型不符 | 400 | `参数类型错误: <name>` |
| 请求方法不支持 | 405 | `该接口不支持 <METHOD> 方法` |
| 唯一约束冲突（重名等） | 409 | `<列>「<值>」已存在，请换一个` |
| 资源不存在（文档/对象/路由） | 404 | 各自语义 message |
| 上传超大小限制 | 413 | `上传文件超过大小限制（最大 <n>）` |
| Content-Type 不支持 | 415 | `不支持的 Content-Type: <type>` |
| 兜底（未知异常） | 500 | `服务器内部错误: <原始 message>`（不裸堆栈） |

更新：2026-10-11-1809-local 深测实证补全 400/405/415 族（此前 JSON 非法/方法不支持/类型错/Content-Type 四类均裸 500，2026-10-11 修复并重验）。
